# AGENTS.md — OET with Dr Hesham website (read me first)

Marketing/landing site for **oetwithdrhesham.co.uk** (OET coaching). Static
HTML + a few PHP endpoints, generated by **Astro** from `site/`. The separate
enrollment **web app** lives at app./api.oetwithdrhesham.co.uk (repo
`/opt/oetwebapp` on the VPS) — **never touch it from here**.

## Architecture (Astro conversion, completed 2026-08)

**`site/src` is the single source of truth. The root `*.html` files are BUILD
OUTPUT, committed for parity/deploy. Never hand-edit root HTML — edit the
partials/data and rebuild.**

- `site/src/pages/*.astro` — 66 thin wrappers incl. 404 (one per page; `ar/` = Arabic, `lang="ar"`), each importing
  its page partials `?raw` and rendering through `site/src/layouts/Base.astro`.
- `site/src/partials/<page>/{meta,head-extra,main,tail}.html` — byte-preserved
  page bodies. This is where page content/CSS edits happen.
- `site/src/partials/chrome/` — shared header (`header-1/2.html`), drawer +
  search overlay (`offcanvas.html`, rendered by `Header.astro`; page partials
  no longer carry a copy), footer (`footer-1/2.html`, joined by `Footer.astro`)
  and community popup. Header, drawer and footer are the ORIGINAL owner-approved
  design plus the three 28 Oct 2026 refinements (see "Original UI restored" below);
  do not restyle them without the owner's explicit approval. Blog, practice-hub and homepage-blog-section styles
  live in `assets/css/oet-redesign.css`, loaded site-wide after `oet-polish.css`.
- **OET Blog**: `site/src/pages/blog/index.astro` (→ `/blog/`) and the homepage
  "Latest from the OET Blog" cards (marker `<!--oet:latest-posts-->` in
  `partials/index/main.html`) are generated from `site/src/data/blog.json` via
  `site/src/lib/blog.mjs`; titles, dates and reading time come from each
  article's own partials. New article: page + partials (breadcrumb Home › OET
  Blog › Category, BlogPosting + BreadcrumbList + visible-verbatim FAQ JSON-LD),
  add it to `blog.json`, `PAGES` in postbuild + verify, `npm run thumbs`,
  rebuild. Rules: `docs/editorial-plan.md` (no thin filler, verify OET facts on oet.com).

### PHP endpoints (served as-is, not built)

`oet-chat-send.php`, `oet-chat-poll.php`, `contact.php`, `oet-chat-lib.php`
(direct web access to lib is 403), `oet-rate-limit.php`. Config via env vars
with graceful `getenv(...) ?: ''` fallbacks. Production sends and syncs mail
through **Microsoft Graph** (`OET_GRAPH_*`, see Known pending items #1);
`OET_SMTP_*` / `OET_IMAP_*` remain as unused fallbacks (the M365 tenant offers
no app passwords, so SMTP AUTH is not an option).
Chat expects **form-encoded POST**, not JSON. Threads stored in
`storage/oet-chat/threads/` (PII — gitignored, never commit or delete).
Contact-form enquiries are saved **before** emailing to
`storage/contact/YYYY-MM.jsonl` (PII — gitignored, never commit or delete), so
no lead is lost if mail delivery fails. Read them with
`ssh root@185.252.233.186 'cat /opt/docker/oetwebsite/storage/contact/*.jsonl'`.
The container has no `sendmail` binary, and the domain's mail is Microsoft 365
with SPF `-all`, so only Graph (sending as the M365 mailbox) delivers email.

### Header Login / Register CTA and the `oet_signed_in` hint cookie

The header carries one call to action in two places, both in
`site/src/partials/chrome/header-2.html`: the nav pill `li.oet-nav-cta-item`
(visible from 1500px; `assets/js/main.js` also clones it into the hamburger
drawer) and `a.oet-header-login` inside `.vl-header-action-item` (logo, CTA,
hamburger order below 1500px). **The visible label is ALWAYS "Login / Register"**
(owner brief 28 Oct 2026): signed in or out, in the header and in the drawer
clone. There is no "My Dashboard" label, no guest/user label spans and no
`html.oet-signed-in` class any more. Each link keeps `data-dashboard-href` and
**must never get an `id`** (the nav is cloned, ids would duplicate). Styles are at
the end of `assets/css/oet-common.css`. `site/scripts/verify.mjs` fails the build
if a link, the no-id rule, the label, the retarget script or the head script is dropped.

The static site cannot see the app's session (different origin, HttpOnly
cookies). The web app (`lib/auth-storage.ts`) sets a **presentation-only hint
cookie** next to its own `oet_auth` and clears it on sign-out:
`oet_signed_in=1`, `Domain=.oetwithdrhesham.co.uk`, `Path=/`, `SameSite=Lax`,
`Secure`, 30 days. The value is always the constant `1` (never a token, id or
PII). The inline script in `site/src/layouts/Base.astro` reads it and only
RETARGETS the link: when the cookie is present, on `DOMContentLoaded` (after
`main.js` built the drawer) and on a bfcache restore, every
`a[data-dashboard-href]` points at `https://app.oetwithdrhesham.co.uk/` (a signed-in
visitor is not sent back through sign-in; session handling is unchanged). No cookie
or JS off means `.../sign-in?next=%2F`. It can be up to 30 days stale; never gate
anything on it, and never read `oet_device_id` as a sign-in signal (it exists for
anonymous visitors too).
