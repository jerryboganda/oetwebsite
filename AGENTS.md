# AGENTS.md — OET with Dr Hesham website (read me first)

Marketing/landing site for **oetwithdrhesham.co.uk** (OET coaching). Static
HTML + a few PHP endpoints, generated by **Astro** from `site/`. The separate
enrollment **web app** lives at app./api.oetwithdrhesham.co.uk (repo
`/opt/oetwebapp` on the VPS) — **never touch it from here**.

## Architecture (Astro conversion, completed 2026-08)

**`site/src` is the single source of truth. The root `*.html` files are BUILD
OUTPUT, committed for parity/deploy. Never hand-edit root HTML — edit the
partials/data and rebuild.**

- `site/src/pages/*.astro` — 56 thin wrappers (one per page; `ar/` = Arabic, `lang="ar"`), each importing
  its page partials `?raw` and rendering through `site/src/layouts/Base.astro`.
- `site/src/partials/<page>/{meta,head-extra,main,tail}.html` — byte-preserved
  page bodies. This is where page content/CSS edits happen.
- `site/src/partials/chrome/` — shared header/footer/community-popup
  (`Header.astro`, `Footer.astro`, `CommunityPopup.astro` in `components/`).
- `site/src/data/pricing.json` — **single source of truth for all 48 package
  prices**. Visible £ amounts AND JSON-LD Offer prices are rewritten at build
  by `site/src/lib/inject.mjs` (`applyPricing`). To reprice: edit this file,
  rebuild.
- `site/scripts/postbuild.mjs` — after `astro build`: appends content-hash
  `?v=` to asset URLs, tags every `wa.me` link with `[page: …]`, generates
  `sitemap.xml` (per-page git dates) and `assets/search-index.json`, copies the
  56 built pages + sitemap to the repo root. `--check-root` asserts root ==
  dist (CI parity). New page = add it to `PAGES` here and in `verify.mjs`.
- `site/scripts/verify.mjs` — asserts pages/assets/JSON-LD/sitemap/pricing, one
  H1 per page, tagged WhatsApp links, FAQ JSON-LD visible verbatim on the page.
  Also: every `fa-*` icon must exist in `assets/css/oet-icons.css` (the icon font is
  subset — unknown icons render blank), and the score-calculator logic in
  `assets/js/oet-score-calculator.js` (regulator minimums — keep in sync with
  `oet-score-requirements.html` when a regulator changes its rules).
  hreflang alternates must exist and link back (Arabic `ar/*` ↔ English
  `service.html`, `oet-course-for-nurses.html`, `oet-course-for-doctors.html`,
  `oet-score-requirements.html`, `oet-test-dates-and-fees.html`, `oet-vs-ielts.html`,
  `oet-writing-tips.html`, `oet-speaking-tips.html`, `oet-sample-tests.html`).

### Build & verify (always run after editing site/src)

```sh
cd site
npm run build            # astro build + postbuild (copies to repo root)
node scripts/verify.mjs
node scripts/postbuild.mjs --check-root
```

Commit the regenerated root pages together with the source change.

### PHP endpoints (served as-is, not built)

`oet-chat-send.php`, `oet-chat-poll.php`, `contact.php`, `oet-chat-lib.php`
(direct web access to lib is 403), `oet-rate-limit.php`. Config via env vars
(`OET_SMTP_*`, `OET_IMAP_*`, …) with graceful `getenv(...) ?: ''` fallbacks —
**SMTP env vars are NOT yet set in production**, so chat/contact email relay
returns `mail_transport_failed` (known, pre-existing; needs user's creds).
Chat expects **form-encoded POST**, not JSON. Threads stored in
`storage/oet-chat/threads/` (PII — gitignored, never commit or delete).
Contact-form enquiries are saved **before** emailing to
`storage/contact/YYYY-MM.jsonl` (PII — gitignored, never commit or delete), so
no lead is lost while SMTP is missing. Read them with
`ssh root@185.252.233.186 'cat /opt/docker/oetwebsite/storage/contact/*.jsonl'`.
The container has no `sendmail` binary, and the domain's mail is Microsoft 365
with SPF `-all`, so only `OET_SMTP_*` (M365 SMTP AUTH) will deliver email.

### Header Login / Register CTA and the `oet_signed_in` hint cookie

The header carries one call to action in two places, both in
`site/src/partials/chrome/header-2.html`: the nav pill `li.oet-nav-cta-item`
(visible from 1500px; `assets/js/main.js` also clones it into the hamburger
drawer) and `a.oet-header-login` inside `.vl-header-action-item` (logo, CTA,
hamburger order below 1500px). Each link has two label spans
(`.oet-auth-cta__guest` / `.oet-auth-cta__user`) plus `data-dashboard-href`,
and **must never get an `id`** (the nav is cloned, ids would duplicate). Styles
are at the end of `assets/css/oet-common.css`. `site/scripts/verify.mjs` fails
the build if a link, the no-id rule or the head script is dropped.

The static site cannot see the app's session (different origin, HttpOnly
cookies). The web app (`lib/auth-storage.ts`) sets a **presentation-only hint
cookie** next to its own `oet_auth` and clears it on sign-out:
`oet_signed_in=1`, `Domain=.oetwithdrhesham.co.uk`, `Path=/`, `SameSite=Lax`,
`Secure`, 30 days. The value is always the constant `1` (never a token, id or
PII). The inline script in `site/src/layouts/Base.astro` reads it: when
present it adds `html.oet-signed-in` (label becomes "My Dashboard") and on
`DOMContentLoaded` (after `main.js` built the drawer) points every
`a[data-dashboard-href]` at `https://app.oetwithdrhesham.co.uk/`. No cookie or
JS off means "Login / Register" to `.../sign-in?next=%2F`. It can be up to 30
days stale; never gate anything on it, and never read `oet_device_id` as a
sign-in signal (it exists for anonymous visitors too).

## Critical debug memory: raw HTML + missing styles

This issue happened on 2026-08-22 and must not recur:

- Symptom: homepage loads as raw unstyled HTML despite the source CSS looking correct.
- Root cause: Astro dev/proxy is configured to serve `/assets` from the legacy local static server at `http://localhost:8000` (see `site/astro.config.mjs`). If `Website/server.js` is not running, CSS/JS requests fail with 500 and the browser renders plain HTML.
- Immediate check: before changing CSS again, confirm the asset server is live and that `/assets/css/oet-mobile.css` responds with HTTP 200.
- Correct local workflow: run the legacy server, then run `astro dev` on the site. Do not assume a visual CSS bug when the asset pipeline is broken.
- Reminder: if the site looks blank or raw, validate the network path and asset delivery before editing any layout rules.

## Production deployment (VPS 185.252.233.186)

Live since 2026-08-14 at commit `0608979` (branch `main`). SSH: `ssh
root@185.252.233.186` (key auth works). Everything is Docker:

- **NPM** (`nginx-proxy-manager-app-1`) owns :80/:443, TLS + HSTS, proxy-host
  25 forwards `oetwithdrhesham.co.uk` → alias `oetwithdrhesham-placeholder`.
- **Container `oetwebsite`** (`php:8.3-apache`), compose project
  `oetwebsite-landing` at `/opt/docker/oetwebsite-stack/docker-compose.yml`
  (NOT project `oetwebsite` — that name belongs to the web app). The compose
  runs `a2enmod rewrite headers expires` and mounts
  `htaccess-support.conf` (AllowOverride All → repo `.htaccess` is honoured:
  caching, gzip, security headers/CSP, 301s, branded 404) and `security.conf`
  (denies `.git`/dotfiles). Backup: `docker-compose.yml.bak-20260814`.
- **Docroot** `/opt/docker/oetwebsite` = git checkout of this repo, `main`.
