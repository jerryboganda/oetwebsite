Reading: the field data Google holds (the only real-user evidence) passes all three Core Web Vitals, and every lab run shows CLS 0 (pricing
0.006). The three non-home URLs report the same field figures as the homepage, which indicates origin-level data rather than per-URL data.
The local DevTools-throttled runs are deliberately harsher than Lighthouse's simulation; under them LCP equals FCP on every page (the LCP
element is text), so the time goes to render-blocking CSS and the HTML itself, which PSI also lists first ("Render-blocking requests", est.
820-940 ms). Pricing carries the most work (largest HTML, TBT up to 690 ms at 4x CPU, PSI "Improve image delivery" est. 282 KiB).

Decision: **no performance change in this release** (no measured LCP/INP/CLS failure; the brief allows only proven bottlenecks and no
homepage layout change). Leads to test first if Search Console's Core Web Vitals report or CrUX turns amber: critical CSS / fewer
render-blocking stylesheets on article pages, the pricing page's image delivery and script work, the homepage HTML weight (182 KB).
Re-measure after deploy only where something changes. Search Console's own Core Web Vitals report was not accessible (section 5, item 1).
